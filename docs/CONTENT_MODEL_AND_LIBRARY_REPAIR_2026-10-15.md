# Общая модель контента и восстановление библиотек

15 октября. Автор сообщил о массовых повторах классов/заклинаний и неразрешённых записях заклинаний в повышении. Потребовал универсального решения для различных библиотек. Это приоритетная сквозная доработка; текущая реализация инвентаря сохранена, но не установлена в основу. Ни данный документ, ни прошедшие прежние проверки не означают готовности новой системы контента.

## Что подтверждает чтение кода

1. `SpellService` объединяет встроенные и сохранённые записи простым добавлением. Альманах намеренно показывал разные ID/источники разными строками. Внутри одного XML есть проверка точных повторов, между перекрывающимися книгами общей модели сущностей нет.
2. `ImportedProgressionService` сохраняет несовпадающие определения класса отдельно, что защищает правила героя. Однако выбор класса выводит их плоским списком одинаковых названий, без предварительной группировки и читаемого различения вариантов.
3. FC5-герой хранит разрешённый на момент импорта ID заклинания либо ID, полученный из имени. Последующая загрузка книги не сопровождается общей безопасной процедурой повторного разрешения этих ссылок. Точное сопоставление `getSpellById` не находит часть старых ссылок. Конкретные причины девяти записей на скриншоте требуют воспроизведения; само отсутствие описанной процедуры подтверждено кодом.
4. Прежний корпус проверял 34 модуля отдельно и два порядка загрузки героя/одной нужной книги. Это не полноценная проверка совместной установки пересекающихся книг. Добавлен отдельный прогон всего архива через настоящий импорт в одноразовое хранилище (`tool/check_catalog_overlap_test.dart`).

## Внутренние сущности

| Слой | Назначение | Устойчивые сведения |
|---|---|---|
| Источник | Установленная книга, архив, модуль, пользовательский материал | ID, версия/хеш содержимого, формат/версия адаптера, происхождение, редакция с достоверностью, лицензия/политика переноса, зависимости |
| Запись источника | Конкретное определение, предоставленное источником | Внешний ID или детерминированный ключ записи, путь/контекст, исходные данные, диагностические сведения, хеш определения |
| Семейство сущности | Одно понятие в каталоге: класс, заклинание, предмет, черта и т. п. | Внутренний ID, тип, система правил, подтверждённые имена/алиасы; отношение к вариантам |
| Вариант правил | Отдельная версия механики | Редакция/вариант, типизированные поля, неизвестные поля, известные отличия и полнота; поддерживающие записи источников |
| Представление | Тексты/названия и медиа нужного языка | Язык, источник/автор перевода, происхождение; перевод не объявляется новой механикой автоматически |
| Ссылка героя | То, что герой действительно выбрал/получил | Семейство, конкретный вариант и версия, исходный внешний ID/имя/источник, состояние разрешения; личные изменения отдельно |
| Личный экземпляр | Вещь или расходуемый запас героя | Собственный ID, ссылка на вариант определения, количество/заряды/экипировка/настройка и личные свойства |

ID файла и локализованное название не становятся глобальной идентичностью. Совпадение названий создаёт кандидатов семейства, но само по себе не разрешает удалять запись или менять правила персонажа. Переименование перевода не меняет приобретённое умение. Один источник может содержать несколько вариантов одного имени, включая разные редакции.

## Разрешение совпадений

- Точное повторение определения: один вариант с несколькими источниками; все источники остаются доступны для объяснения происхождения и удаления книги.
- Доказанное совпадение механики при разных переводах: общий вариант и несколько представлений. Условия доказательства типизированы по сущности; один текстовый хеш не решает все случаи.
- Разные механики/редакции: отдельные варианты одного семейства, понятные отличия и явный выбор. Ни порядок импорта, ни последняя запись не определяют победителя.
- Частичное определение/дополнение: связь с зависимостью, сведения об отсутствующих полях; дополнение не превращается в полный вариант с выдуманными значениями по умолчанию.
- Неуверенное сопоставление: кандидаты и причина неопределённости. Данные сохранены, применение спорной механики не автоматизируется.
- Алиасы имён двуязычны; опечатки и похожесть используются для поиска/предложения, без автоматического доказательства равенства.

Нормализация чисел, единиц, значений перечислений, компонентов, редакции и списков выполняется адаптерами и оставляет происхождение. Отсутствие поля отличается от явного нуля/false/пустого списка. Текстовый эффект без поддерживаемой структуры остаётся читаемым правилом, а не обещанием полной автоматики.

## Пользовательский путь

Альманах показывает одно семейство в выдаче, с раскрытием доступных вариантов и источников. Фильтр книги учитывает все источники варианта. Карточка показывает выбранную редакцию/различия; действия изучения, подготовки и применения относятся к конкретному варианту и классу героя. Если у героя уже выбран вариант, он читается явно и не заменяется ради красивой выдачи.

Класс выбирается сначала как направление развития, затем при необходимости — конкретная версия правил с понятной книгой, редакцией и существенными отличиями. Добавление второй версии уже имеющегося класса не маскируется под новый мультикласс. Прежние закреплённые правила героя остаются при нём.

Неразрешённые записи героя сохраняют исходное имя и контекст. Экран не выводит девять неразличимых «заклинаний из неподключённой книги». Подключение нужной книги запускает проверку ссылок с предварительной оценкой; однозначные подтверждённые соответствия восстанавливаются, неоднозначные требуют выбора с понятными вариантами. Исправление ссылки отдельно от решения, какой класс дал заклинание.

Библиотеки показывают добавленные понятия, точные повторы, новые варианты, частичные определения, зависимости и конфликты. Повторный импорт безопасен; удаление книги проверяет оставшиеся источники и ссылки героя. Оставшееся без книги определение не исчезает из листа молча.

## Поддержка разных форматов

Общий контракт адаптера: обнаружение формата/версии → предварительное чтение → записи с происхождением и неизвестными полями → нормализация → поиск семейств/вариантов → план изменений и диагностика → согласованная запись. UI не предлагает пользователю программирование.

FC5 XML-компендиум, FC5-персонаж, ZIP с модулями, collection/source с зависимостями и нативный QDND — отдельные входные семейства с отдельными возможностями. Другие форматы подключаются по этому же контракту после проверки реальными примерами. Универсальная внутренняя модель не означает обещания прочитать любой существующий файл без нового адаптера. Незнакомая версия явно диагностируется и не частично устанавливается как будто всё готово.

## Внедрение без потери листов

1. Зафиксировать воспроизведение полного архива, повторов и неразрешённых ссылок; добавить смешанные публичные книги, разные порядки, переводы и конфликты.
2. Ввести общий индекс записей/семейств/вариантов поверх существующего хранилища. Исходные записи и старые ID сохранять; сначала чтение и диагностика.
3. Устроить явную и обратимо проверяемую миграцию ссылок. Отмена/ошибка сохраняет прежние данные; подтверждённый план проверяет актуальную ревизию каталога. История повышений и личные экземпляры тоже входят в ссылки.
4. Перевести каталоги и выборы приложения на этот индекс: Альманах, создание, повышение/мультикласс, черты/умения, предметы, происхождение магии и перенос. Группировка UI не подменяет этот шаг.
5. Прогнать сквозные действия, отдых, обновление/удаление книги, перезапуск и перенос. Только затем выпускать Cycle для пользовательской приёмки, после неё — основу.

Не удалять повторы из пользовательского хранилища по названию. Не перепривязывать героя к первому найденному варианту. Не сбрасывать библиотеки и не просить повторного импорта как штатного исправления. Изменения формата/миграций версионировать; неизвестное сохранять.

## Матрица обязательной проверки

Один пакет дважды; другой filename того же содержимого; сборник + отдельные модули; встроенное + перевод; RU/EN отдельно и вместе; одно имя/разные круги; одно имя/разные механики одного круга; редакции 2014/2024; дополнение без основы/с основой; опечатка/новое имя; неизвестное поле/версия; герой до/после книги; старый ID после обновления; две книги с общим определением и удаление одной/обеих; закреплённые правила класса; заменяемые умения/мультикласс; изучение/подготовка/расход/отдых; история повышений; одинаковые личные предметы; ошибка записи/перезапуск; нативный перенос с отсутствующими книгами и коллизиями ID. Большие каталоги: индекс и кэш не должны заново разбирать все XML при каждом выборе или кадре UI.


## Первая воспроизведённая контрольная точка

Полный прогон через реальный импорт в одноразовое хранилище: установлены 33 источника; получены 58 строк классов (в частности, шесть «Чародеев»), 1678 записей заклинаний, 453 группы повторяющихся русских названий/кругов. Во всех 453 группах присутствуют точные повторы определений. Сборник и его отдельные модули действительно пересекаются; одних проверок внутри XML недостаточно.

Герой, импортированный заново **после** всего архива, имел 17 известных заклинаний и ноль неразрешённых ссылок. Это не воспроизводит старые ссылки сохранённого героя. Идёт отдельный прогон героя, импортированного **до** полного архива; его результат будет добавлен по завершении. Телефон и личное хранилище не менялись.

Добавлен первый общий **индекс чтения** `lib/core/content/content_catalog.dart`, одинаково представляющий заклинания, классы, предметы, расы, предыстории и черты. Запись источника, семейство и точный вариант различаются. Семь проверок подтверждают: несколько источников одного варианта; сохранение домашних/редакционных отличий; связь переводов; удаление одного источника; значимость неизвестных полей; неоднозначность одинаковых ID разных книг; независимость группировки от порядка импорта.

Это основание последующих изменений, а не выполненная миграция. Индекс пока не заменяет рабочие каталоги приложения и не переписывает ссылки героя. Ключи групп чтения временные; постоянные ID сущностей будут введены вместе с согласованной миграцией и журналом изменений. Сопоставление механик переводов по типизированным правилам ещё предстоит, точный вариант сравнивается консервативно. Массовое удаление повторов и переключение правил героев не выполнялись.


## Первый исправляющий проход после воспроизведения

Повторный сквозной прогон того же полного архива с новым восстановлением: сохранённый до книг герой начинал с **9** неразрешённых ссылок, после установки модулей стало **0**, дополнительный финальный вызов ничего не менял (повторно выдавать/переписывать нечего). Новый импорт после книг также разрешает все 17 известных заклинаний. Сохранено 33 источника, все 1678 исходных записей заклинаний и 58 записей классов; массового удаления повторов нет.

Индекс чтения разделяет эти 1678 записей на **604 семейства и 773 точных варианта**. Это консервативное сравнение известных определений, не автоматическое доказательство эквивалентности разных переводов. Девять старых ссылок имели по три одинаковых кандидата и были безопасно восстановлены. Если варианты отличаются, автоматическое восстановление не выбирает первую книгу.

`ContentReferenceRepair` подключён к установке книг, обычному запуску и удалению источников. Уже разрешённый ID сохраняет выбранные правила. Пропавший источник может быть заменён только точным сохранившимся вариантом по зафиксированному хешу. В списках/книге источников, концентрации, мастерстве и фирменных заклинаниях сохраняется согласованность; флаг использованного фирменного заклинания объединяется через OR. История повышений переназначается без повторного применения развития. Текущие ресурсы/ОЗ/журнал/вещи не меняются. Ошибка записи возвращает предыдущее состояние; неизвестные версии и неоднозначности сохраняются и откладываются.

В книге героя хранится минимальное происхождение исправленных ссылок: исходные ID, имена и хеш точного определения. Тексты чужих книг в эту метаинформацию не копируются. Нативный перенос согласованно переназначает эти ключи. Старые читаемые имена используются на шаге определения владельца заклинания вместо одинаковых безымянных заглушек.

Альманах показывает семейство одной строкой, точные копии объединены с указанием книг, отличающиеся варианты требуют явного выбора. Фильтры продолжают работать по исходным записям — выбранная книга/круг не теряется из-за представителя группы. Выбор класса тоже группируется по семейству и отдельно открывает варианты правил с книгами и редакциями. Для имеющегося класса используются закреплённые правила героя; повреждённый снимок не подменяется другой книгой. Создание персонажа, прочие типы каталогов и отдельные списки выбора ещё нужно последовательно перевести на ту же модель; текущая готовность не объявляется повсеместной.

Прошли 13 проверок индекса/восстановления и 71 целевая проверка интеграции с магией и развитием. Четыре дополнительные UI-проверки подтвердили одну строку семейства, сохранённые записи источников, явный выбор действительно отличающегося эффекта, RU/EN и крупный шрифт при выборе класса. Полный регрессионный прогон после этого прохода: **764 проверки прошли**; анализ кода не обнаружил ошибок/предупреждений, остаются две прежние информационные отметки использования устаревшего `axisAlignment`. После дополнительной доводки точности цены Кузницы прошли ещё 19 целевых проверок инвентаря (в том числе новая проверка дробной цены, без округления в пользу потерянных монет).

Это первый внедрённый слой. Постоянные ID всех сущностей, полноценная нормализация объявленных/неизвестных полей, семантическое сопоставление переводов, разрешение частичных дополнений и UI предварительной миграции остаются открытыми. Не объявлять библиотечный блок завершённым по этому исправлению.


Независимый контрольный корпус после исправлений: все 4 сценария прошли (15 публичных компендиумов, сканирование 34 модулей архива, два порядка импорта нужной книги и героя). Прежнее сравнение всей сериализации заменено проверкой неизменности игровых значений с отдельной проверкой законно восстановленных ссылок: иначе правильная замена старого ID сама считалась бы изменением игры. Для каждого заменённого известного заклинания проверены сохранённое происхождение, единственный новый ID и наличие определения; количества известных и подготовленных заклинаний сохранены. Это дополнение проверок, а не разрешение менять ресурсы/классы/имущество.

### Остающиеся обязательные ограничения этого слоя

FC5-адаптер нового персонажа ещё использует прежнее сопоставление имени с первым определением. Это нужно заменить явным разрешением неоднозначного варианта с сохранением полного исходного контекста; текущий первый слой ремонта **не объявляет такой импорт безопасно универсальным**. Смысловое сравнение переводов должно учитывать полноту данных и редакцию, прежде чем менять этот путь: простая строгая проверка текста сделала бы обычные переводы неоднозначными. Аналогично, справочные «болванки»/частичные классы требуют явного типа записи, а не фильтра по слову в названии. Эти работы включены в продолжение модели и приёмки.

Нативный Review с искусственными пересекающимися книгами и новым инвентарём собран отдельно. Основной пакет и пользовательский Cycle на Pixel в ходе этого ремонта не обновлялись. Следующая установка выполняется после проверки и согласования рабочего среза; прежнее обновление 04:12 не содержит этих новых изменений.
