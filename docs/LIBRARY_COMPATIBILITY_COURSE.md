# Библиотеки после начала игры — совместимость и развитие

9 октября 2026. Автор отдельно попросил заранее классифицировать сторонние библиотеки и учитывать их подключение к уже играющему герою. Документ уточняет L01–L08, P01–P08, T01–T09 общего WORKING_VERSION_TODO.md. Это курс и границы, а не заявление о поддержке любой неизвестной механики.

## Базовое поведение

Подключение книги расширяет доступный справочник и варианты. Оно само по себе не повышает героя, не выдаёт выбранные умения, не восстанавливает ресурс, не снимает ручные поправки и не заменяет правила уже взятой способности. Изменение используемых правил требует понятного сравнения и явного применения; это продолжение принятой политики сохранности и воли игрока. UI такого согласования ещё предстоит реализовать, поэтому текущая защита не считается полной привязкой правил героя.

## Классификация

| Случай | Пример | Ожидаемое поведение |
|---|---|---|
| Новый контент | Новый предмет, заклинание или самостоятельный класс | Доступен для ознакомления/выбора; не выдаётся героям от загрузки файла |
| Дополнение к профилю | Новый подкласс/варианты для существующего класса той же редакции | Совместимость определяется заявленными связями и правилами, не одним названием. Существующие выборы не изменяются |
| Перевод и aliases | Другой язык той же определённой версии заклинания | Одна механическая сущность с локализованным представлением; совпадение имени само по себе не подтверждает идентичность |
| Конкурирующий вариант | Домашний Паладин с другой костью хитов, иная прогрессия или редакция | Отдельный профиль и источник. Не смешивать половину одной таблицы с половиной другой |
| Обновление установленной книги | Исправление текста или новая механика способности | Различать редакционное и механическое изменение. Для используемых правил — сравнение, сохранение текущего экземпляра, явное применение |
| Неизвестная механика | Произвольная цепочка эффектов, новый синтаксис/тип ресурса | Текст сохраняется. Автоматизация обозначена только там, где правило действительно распознано и проверено. Понятная ручная настройка поддерживаемых свойств не превращается в IDE |
| Частичный источник | XML с одним подклассом и без базовых таблиц | Отсутствие данных не означает нулевое значение и не разрешает угадывать редакцию. Показать недостающие зависимости |
| Удаление/отключение/перенос | Книгу убрали после нескольких сессий | Экземпляр героя, расход, выбранные способности, медиа и заметки сохраняются; отсутствующий источник не подменяется одноимённой книгой |

## Идентичность и владение данными

Нужна идентичность «поставщик/источник + стабильный ID сущности + редакция/профиль + версия/хеш содержимого». Имя файла, перевод названия, дата импорта и похожий текст по отдельности недостаточны. Хеш XML уже используется для точного повтора импорта, но он не определяет автоматически преемственность разных версий книги.

Разделяются определения книги, выбранная версия правила у героя, его фактический расход и ручные поправки. Общий шаблон не должен владеть остатком конкретного героя. Для развития нужны выбранный профиль класса и происхождение каждого решения; для магии — принадлежность заклинания/способа применения и пула, а не только плоский список ID. Нужны сохранённые определения для автономного листа и переноса, включая ситуацию без исходной библиотеки.

Профиль 2014 и профиль 2024 независимы. Не определяем редакцию по имени «Wizard», уровню первой найденной способности или оформлению файла. Неизвестная редакция остаётся неизвестной до явного описания/выбора.

## Что реализовано в этой итерации

- ProgressionCatalogStamp фиксирует определения доступного каталога при открытии повышения. Быстрая проверка поколений каталогов применяется в UI, проверка содержимого — перед записью в общей очереди. Большие книги не хешируются заново на каждом кадре.
- Подключение/удаление/перезагрузка источников во время выбора инвалидирует прежнее подтверждение. Герой не меняется; UI объясняет, что повышение нужно открыть заново и проверить новые варианты. Прямая случайная мутация определения тоже обнаруживается при подтверждении.
- ImportedProgressionService отличает новый класс, частичное дополнение и наблюдаемый конфликт определения: кость хитов, явно заданное заклинательство и перенос той же идентифицированной способности на другой уровень. Конфликтующий вариант сохраняется отдельно, а не прививается к встроенной таблице по имени. При совпадении сырых ID для представления каталога используется квалифицированный ID источника; исходная запись библиотеки не переписывается. Импорт выдаёт предупреждение.
- Настоящий FC5-импорт и последующее удаление книги проверяются на уже сохранённом герое: ОЗ 0, временные ОЗ, ручная КД, превышение ячеек, деньги и запись остаются прежними. Изменение источника во время ожидания очереди не допускает запись устаревшего повышения.

## Что нельзя считать решённым

Структурное сходство не доказывает совместимость. FC5-парсер сейчас теряет часть исходных признаков отсутствия данных и использует значения по умолчанию; например, отсутствующая hd может выглядеть как кость d8. Поэтому обнаруженная разница означает необходимость отдельного рассмотрения, а не доказательство другой редакции. Отчёт «частичное дополнение» тоже не означает проверенную поддержку всей книги.

Полная привязка использованной версии к герою, обзор обновления/конфликтов, выбор правил для конкретного героя, источники с одинаковыми именами/локальными ID, обратимые миграции, полный автономный снимок заклинаний/классов и честный перечень исполняемых возможностей остаются открытыми. Особенно важны изменения умения с тем же ID и уровнем, обновление ранее удалённой книги и большие каталоги. Для FC5 XML частичный отказ установки теперь покрыт отдельной защитой ниже; она не распространяется автоматически на все форматы и операции.

## Пользовательский путь без перегрузки

В библиотеках: перед подключением коротко показать, что добавляется, что конкурирует с установленным и какие зависимости неизвестны. Для нового контента — простое подключение; для используемого переопределения — отдельное сравнение. На листе остаются только относящиеся к этому герою отметки. Детали происхождения/версии доступны по запросу, без технических хешей в обычном игровом интерфейсе.

В повышении: показывать варианты из выбранных источников с объяснением требований. Нельзя превращать пропавший вариант в успешно выполненный выбор или автоматически уменьшать требуемое количество. При изменении книги черновик сохраняет смысл выбора для повторной проверки; автоматически подтверждать новый результат нельзя.

## Следующие проверки

Проверить загрузку до создания/после импорта героя/между сессиями/в открытом повышении; два источника с одинаковым именем; два разных перевода; конфликт 2014/2024; изменённое умение с тем же ID; добавление/удаление/обновление подкласса; неизвестные формулы и отсутствующие ссылки; сохранённый расход/превышения/ручные максимумы; экспорт и восстановление без книги; аварийное завершение и нехватку места посреди импорта; нагрузку больших справочников. Все случаи входят в сквозную матрицу, а не только в тест чтения XML.

## Продолжение 9 октября — целостность импорта и пересечения книг

Исправлены два независимых пути потери данных: установка FC5 XML раньше записывала отдельные части каталога по очереди без общего восстановления; поиск дублей мог отбросить определение только из-за совпадения имени с другой книгой или встроенными данными.

Теперь FC5 XML устанавливается через сохраняемый журнал восстановления. До изменений записываются прежние значения затрагиваемых ключей, содержимое пишется перед метаданными источника, фиксируется завершение, затем журнал очищается. При исключении выполняется откат; после прерывания незавершённая операция восстанавливается при открытии хранилища, до чтения каталогов. Запись о завершённой операции при перезапуске означает только очистку журнала, а не удаление успешно установленной книги. Неподдерживаемый/повреждённый журнал не очищается вместе с данными: восстановление останавливается с ошибкой. Понятный пользовательский экран такого восстановления остаётся T05/T08.

Установка и удаление источников используют общую очередь; повторные FC5-импорты также сериализованы вместе с проверкой повтора и перезагрузкой каталогов. Даже прямой вызов установки проверяет повтор fingerprint, уникальность ID и принадлежность всех определений устанавливаемой книге. Существующие ID не перезаписываются в обход отдельного сценария обновления. Незавершённые записи не выдаются обычными методами чтения списка каталога.

Независимые книги сохраняют собственные определения, даже если часть содержания совпадает. Удаление первой не лишает вторую перекрывающегося содержимого. Это основа сохранности, а не законченная группировка вариантов в UI: аккуратный показ совпадений/выбор источника ещё предстоит. Точный повтор одного файла по-прежнему отклоняется. Внутри одного источника одинаковые повторения сворачиваются; разные определения с одним ID отклоняют всю установку с диагностикой, вместо выбора последнего значения.

Агрегация FC5-классов проверяет известные противоречия кости хитов/заклинательства и повторов одной способности на одном уровне. Одинаковые названия способностей разных подклассов становятся общим умением только при совпадении разобранного содержания. Разные свойства остаются у своих подклассов. Это не доказательство полной совместимости классов: отсутствующие поля, редакции, неизвестные XML-поля и зависимости всё ещё требуют дальнейшей работы.

### Воспроизводимые сценарии

| Сценарий | Проверенный результат |
|---|---|
| Ошибка после записи предметов и заклинаний | Прежний каталог сохранён, новые записи/метаданные/fingerprint убраны; повторная установка проходит |
| Ошибка при публикации метаданных источника | Незавершённая книга не остаётся установленной |
| Перезапуск с сохранённым журналом незавершённой операции | Восстановлены прежние типизированные данные Hive, новые записи удалены |
| Перезапуск после завершения, до удаления журнала | Установленная книга сохраняется |
| Повреждённая запись восстановления с запрещённой областью | Ни один существующий элемент не изменяется; журнал сохранён для диагностики |
| Два источника с одним названием, разные одноимённые заклинания | Оба определения и их свойства сохранены с разными ID/источниками |
| Одинаковое заклинание в двух самостоятельных книгах | После удаления первой копия второй остаётся доступна |
| Точные повторения внутри книги / разные определения с одним ID | Первые сворачиваются, вторые отклоняют книгу до записи |
| Разная кость хитов в одноимённых узлах класса | Диагностика конфликта; источник не установлен |
| Разное одноимённое умение в двух подклассах | Обе версии остаются у своих подклассов |
| Конфликт одной способности внутри одного класса/уровня | Отклонение, включая повтор внутри единственного XML-узла класса |
| Одновременный импорт одного XML / прямые установки с одним fingerprint | Только одна установка; отказ не блокирует следующую операцию |
| Чужой источник у определения / повтор ID в списке установки | Отказ до записи |
| Вложенный механический ID в сравнении | Не теряется при нормализации; порядок полей не влияет на сравнение |
| Поздняя загрузка и удаление на уже играющем герое | Ранее проверенные расход/превышения/ОЗ/КД/деньги/журнал остаются прежними |

Проверки используют реальные временные Hive-базы и FC5-импорт. Прерывание моделируется сохранённым журналом с последующим закрытием/повторным открытием базы; это не испытание физического отключения телефона или повреждения файловой системы. Ошибка записи моделируется после реальных записей нескольких областей. Большие архивы и реальные отказы носителя требуют отдельных проверок.

### Открытые границы этого изменения

- Журнал охватывает установку одного FC5 XML-источника. Удаление книги, весь многофайловый архив, QDnD bundle, персонажи и медиа ещё не объединены этой транзакцией; сбой посреди удаления остаётся отдельной задачей I05/T06.
- Загрузка каталога в память и оповещение всех экранов пока не являются единым публикуемым снимком. Блокировка устаревшего повышения остаётся обязательной; всю архитектуру уведомлений это изменение не заменяет.
- Снимки использованных правил у героя, профили редакций, зависимости и согласованный переход между версиями не завершены. Следующий приоритет — различать отсутствующие данные и явно заданные значения, затем привязать выбранную версию правил к герою.
- Дедупликация сравнивает разобранные поддерживаемые поля. Потеря неизвестных исходных XML-полей всё ещё L06; нельзя объявлять два исходных правила равными только по нынешнему неполному представлению.

Полный прогон этой итерации: **426 прошли, 2 прежних пропуска**. После финальной защиты прямой установки: **23 затронутые проверки прошли**, анализ 10 изменённых файлов без замечаний. Добавлено 17 новых проверок этой итерации. Логи: evidence/catalog-scenarios-full-tests.log, catalog-scenarios-final-focus.log, catalog-scenarios-final-analyze.log. UI в этой итерации не менялся, новую сборку на Pixel не устанавливали.

## Требование системного завершения

Клятва покорения — воспроизводимая регрессия, не предмет специальной реализации. Завершение импорта требует проверки общих механизмов на классах/подклассах разных источников, разных формах FC5 XML/архивов и разных порядках событий. Матрица: библиотека до/после героя; одна/несколько книг; перевод полон/частичен/отсутствует; описание находится у класса/подкласса/умения/вложенного элемента; одинаковое имя при равном/разном содержимом; источник обновлён/отключён/удалён; личный снимок закреплён/отсутствует/повреждён; сохранённый расход/ручные параметры; частичная ошибка/повтор/перезапуск/перенос. Неизвестные данные сохраняются, неподдерживаемое явно объясняется, успешный отчёт не скрывает потерь.
