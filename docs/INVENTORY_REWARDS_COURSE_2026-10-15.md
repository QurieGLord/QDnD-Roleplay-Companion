# Инвентарь, Кузница и награды — следующий отрезок

15 октября автор разрешил переходить к инвентарю по мере исправления мультикласса и отката и напомнил о подготовке наград заданий. Принятый Expressive/iOS курс, палитры, сдержанное движение, тактильность и RU/EN сохраняются. Существующую Кузницу развиваем.

## Сначала устранить реальные риски

При чтении текущего `InventoryTab` найдены прямые изменения имущества до записи, поиск экземпляра по каталожному `item.id`, удаление всех совпадений через `removeWhere`, отдельные сохранения количества/экипировки/настройки. Награда с двумя одинаковыми клинками должна создавать два независимых экземпляра; удалить один не означает удалить оба. Стоимость, предмет и отметка получения должны сохраняться одной операцией. Это обязательная основа следующего интерфейса.

## Пользовательский путь

1. Кошель в компактной поверхности с общей стоимостью и доступными номиналами по запросу. Ручная поправка остаётся явным действием игрока.
2. Снаряжение на персонаже и содержимое рюкзака читаются раздельно; поиск/фильтры не создают второй независимый список. Количество и заряды видны спокойно, без ряда калькуляторных кнопок.
3. Нажатие открывает читаемую карточку предмета, удержание с вжатием — быстрые действия. Экипировка, настройка, использование и исправление количества показывают реальный результат. Один видимый путь добавления, без дублирующегося «+».
4. Кузница последовательно раскрывает свойства предмета: основа, постоянные бонусы, условия экипировки/настройки, активные умения/заряды и восстановление. Без пользовательского программирования. Изображение и собственное описание сохраняются.
5. Полученная награда приходит в тот же инвентарь и кошель. Для неё не создаётся отдельный набор временных предметов с другой логикой.

## Договор владения предметами

- Определение из книги/Кузницы и принадлежащий герою экземпляр имеют разные идентификаторы. Копии не делят экипировку, настройку, заряды и изображения.
- Объединение стопок разрешается только для совместимых определений и личных свойств. Расход заряда одного предмета не меняет другой. Продажа/передача/разделение стопки сохраняет происхождение.
- Общая операция в очереди героя меняет имущество, деньги, эффективные бонусы и журнал получения. Ошибка возвращает связанные значения; незавершённые операции и медиа требуют восстановления.
- Старые предметы получают идентичность при явном согласованном применении миграции; чтение карточки не удаляет дубликаты и не переписывает книгу.
- Нативный перенос сохраняет экземпляры и связи. Коллизии при дублировании героя/источника переназначаются согласованно.

## Награда задания: обещание и получение

Завершение задания **не начисляет** награду. Обещание может содержать деньги, предметы, свободное описание или неизвестный результат. Факт получения — отдельное действие с предварительным итогом.

В задании появляется компактная отметка награды. «Получить» открывает аккуратную форму с фактически выданными деньгами/предметами; подтверждение одновременно обновляет кошель, инвентарь и запись о получении. Повторное нажатие, перезапуск и повторный импорт не выдают то же событие заново.

Частичное получение учитывается несколькими независимыми записями с собственными ID. Переплата/дополнительный дар мастера возможны явно; дублирование одного события и новая осознанная выдача различаются. Изменение обещания не переписывает уже выданное имущество. Повторное открытие задания, смена статуса и откат уровня не отменяют получение. Исправление ошибочного получения — отдельная понятная операция, не скрытый побочный эффект.

## Техническая подготовка

| Данные/операция | Требование |
|---|---|
| Обещание награды | Версия, ID задания, типы денег/предметов/описания/неизвестного результата; исходный текст сохраняется |
| Получение | Устойчивый ID события, снимок выданного, созданные ID экземпляров, фактические суммы, связь с заданием/журналом |
| Деньги | Целые значения номиналов/стоимости, без дробных ошибок; смена представления не создаёт монеты |
| Предметы | Личные ID экземпляров и ссылка на определение; составные награды, количества, свойства Кузницы и медиа |
| Применение | Одна очередь и согласованная запись героя; нет записанного «получено» без имущества или имущества без записи |
| Перенос | Согласованное переназначение ID заданий, предметов и событий; получение не запускается при чтении файла |
| Неизвестные версии | Сохранение сведений и понятная недоступность автоматического действия, без угадывания |

## Матрица приёмки

Два одинаковых предмета; разные заряды/свойства; ноль/превышение количества; часть стопки; текущая настройка/экипировка; ручная КД; составная/частичная/неизвестная награда; выдано больше обещанного; повторное нажатие; два экрана; ошибка записи/медиа; перезапуск; повторный импорт; перенос с коллизией ID; удалённое/снова открытое задание; откат уровня после получения; RU/EN, длинные имена, крупный текст и уменьшение движения.

Этот документ фиксирует подготовку и порядок реализации. Новый интерфейс инвентаря и автоматическое получение наград пока не объявлены реализованными. Первый следующий рабочий шаг — личная идентичность предметов и общий путь изменения имущества, затем нативный редизайн основных взаимодействий.


## Первый рабочий проход — выполняется 15 октября

Автор прямо запросил виджет экипированного снаряжения, исключив фигуру со слотами тела. Реализуется «При себе»: оружие крупной рабочей карточкой, доспех/щит парой при достаточной ширине, список остальных экипированных вещей и отдельные настройки. Кошель и вес компактны; рюкзак прокручивается целиком, фильтры убраны в понятную форму, одно добавление из листа.

Вводится личный `instanceId` стопки (Hive Item 18) отдельно от каталожного `id`; сохраняется `requiresAttunement` (Hive Item 19), которое прежняя Кузница теряла. Старые экземпляры получают ID только при подтверждённой операции с имуществом/кошельком, а не при чтении. Ошибка записи возвращает прежний список и идентичности. Повторное/устаревшее действие не выбирает другой предмет по каталожному ID.

Обычный режим экипирует один доспех и один щит; оружие и прочие предметы остаются под ручным контролем игрока. Настройка считается и в рюкзаке. Четвёртая настройка требует явного выбора исключения стола. Ручная КД сохраняется. Нулевое количество оставляет читаемую пустую стопку, прекращая её экипировку/настройку; удаление отдельно. Разделение создаёт новую ненадетую/ненастроенную стопку без изменения суммарного количества.

Кузница перерабатывается для свойств, которые поддерживает текущая модель: урон/тип/универсальный урон/дистанции/теги оружия, КД/вид доспеха/Ловкость/ограничения, редкость/магия/требование настройки, описание/количество/вес/цена. Изменение личной вещи не переписывает библиотеку. Активные заряды, произвольные условные бонусы, предметные заклинания и полная медиа-форма остаются следующей работой; их готовность не заявляется этим проходом. «Использовать один» списывает количество, но не угадывает лечение или иное действие произвольного предмета.

QDND-формат 5 сохраняет личные экземпляры и требование настройки; читает прежние версии 1–4. Прежние приложения не должны незаметно терять новую структуру. Откат повышений не меняет имущество. Подготовка наград продолжается по договору выше; начисление наград в UI ещё не реализовано. Визуальная приёмка нового инвентаря и Кузницы проводится по нативным снимкам и Cycle отдельно.
