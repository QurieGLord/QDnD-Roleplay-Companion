# Альманах, личные списки и магия — первый рабочий отрезок

12 октября. Автор включил полный ремастер Альманаха в следующий этап вместе с магией и сквозным мультиклассированием. Также закреплён повсеместный пересмотр UI/UX: [реестр экранов](UI_UX_COVERAGE.md). Принятый прежний Cycle уже перенесён в основную установку; этот новый отрезок пока проверяется отдельно.

## Реализовано

- Новая композиция Альманаха с контекстом героя, поиском, выборкой доступности и кругами. Фильтры по школе/классу/книге/концентрации/ритуалу раскрываются по группам. Изменения фильтров применяются явно; закрытие отменяет черновик. Сброс синхронизирован с видимым полем и отложенным поиском.
- Список строит отдельные строки по мере прокрутки. Сохранены разные ID/книги с одинаковым названием; поиск их не объединяет. Личные правила классов разрешаются один раз на каталог, а не повторно для каждой строки. Неизменённая выборка кешируется; пустой запрос не запускает морфологию/подбор слов для всего каталога.
- Офлайн-поиск по обоим названиям, независимо от языка интерфейса: формы слов, ограниченная близость написания и небольшой явный словарь терминов магии. Поиск в описаниях включается отдельно. Это лексический поиск, не языковая модель и не обещание понимания произвольного смысла.
- Доступность вычисляется для каждого класса по **его** уровню и сохранённым правилам. Высокие общие ячейки не открывают личные круги второго класса. Учтены обычная, половинная/третья прогрессия, отдельные условия школ поддержанных подклассов и Арканум колдуна. Арканум не выдан как обычная ячейка/бесплатный выбор. Повреждённые снимки и неизвестная редакция не заменяются догадкой.
- Описание заклинания: иерархия названия, пары времени/дистанции/длительности/компонентов, материалы, концентрация/ритуал, полный текст, усиление, книги и объяснения классов. Длинный заголовок/текст прокручиваются вместе. Для неполного перевода показывается имеющийся оригинал. Перевод коротких значений не отбрасывает хвост условия реакции и не подставляет русский текст в английский интерфейс.
- Добавлена явная принадлежность личных списков классу либо решению стола. Одно заклинание может быть в двух списках; удаление/подготовка одного не изменяет другой. Старые списки читаются без автоматического приписывания классу. Явная привязка одной старой записи сохраняет её подготовку и остальные записи.
- Редактирование списка и подготовки выполняется общей очередью с записью/возвратом связанных значений при отказе. Обычная подготовка учитывает собственный уровень/характеристику и минимум один в поддержанных базовых правилах; ручное превышение требует явного решения. Неподписанная старая подготовка смешанного героя не превращается в дополнительную бесплатную вместимость. Всегда подготовленное содержимое в модели защищено от обычного удаления; автоматическое наполнение всех таких даров ещё открыто.
- Описание из вкладки листа использует тот же редактор принадлежности/подготовки. Прежнее прямое изменение только общего списка из этих действий убрано. Индикатор подготовки открывает описание с выбором источника; ускорение частого однозначного случая можно довести после подключения полного применения.

## Данные и перенос

Добавлен `Character.spellbookData`, поле Hive 82, с отдельной версией содержимого. Отсутствующее поле читается как старый лист без принадлежности. Изменения не выполняются от открытия. Общие `knownSpells`/`preparedSpells` пока сохраняются как проекция для существующего листа; их наличие **не завершает** выбор источника при применении заклинания.

Клонирование/предварительный просмотр изолируют новую карту. Нативный перенос сохраняет её и переназначает ID заклинаний/классов при импортных конфликтах. Неподдерживаемая версия карты отклоняется до редактирования. Перед выпуском нового среза отдельно завершить контракт версий самого файла переноса: прежний читатель schema 2 не знает происхождение и не должен молча считаться сохраняющим его при обратном переносе.

## Проверки

Общий прогон после основной реализации: **546 прошли, 2 прежних пропуска**. После последней доводки подготовки/фильтров, доступности поиска и склонений — **38 связанных проверок** Альманаха и настоящего переноса QDnD. Включены обе очередности классов, чужие круги, Арканум, школы, повреждённые снимки, RU/EN/опечатки/синонимы, дубли книг, отказ записи/очередь, привязка старой подготовки, независимость владельцев, Hive-перезапуск, изоляция копии, реальный bundle и его remap, большой шрифт/клавиатура/длинное название, отмена фильтров. Анализ: только два прежних уведомления `axisAlignment`, новых ошибок/предупреждений нет. После оптимизации повторных выборок связанные проверки выполнены отдельно. По нативной проверке дополнительно разделена область доступности поля поиска и заголовка; счётчик заклинаний получил правильные русские склонения. Итоговые 38 связанных проверок прошли; анализ сохранил только два прежних уведомления.

Нативный просмотр запускается на эмуляторе в отдельном `com.qdnd.qd_and_d.expressivereview`. Первый пример — Волшебник 3 / Жрец 2 с отдельной подготовкой. Снимок каталога позднее обновлён на примере Волшебник 3 / Колдун 3 из сквозной проверки. Его специальный entry point существует только в проверочной копии; в основной программе/на Pixel новые изменения не установлены. Снимки не являются художественным макетом. На эмуляторе проверены реальные снятие/повторная подготовка с изменением 1/7 → 0/7 → 1/7 и обратной связью после сохранения.

3. Заполнить и связать гарантированные/добавочные заклинания подклассов, рас, черт, предметов и особых умений. Сейчас их неизвестные условия не превращаются в автоматическое разрешение. Мастерство, Фирменные заклинания, Арканум и ритуал — отдельные способы применения, не следствие добавления в список.
4. Не угадывать правила сторонних книг/2024; нужны явные определения списка, прогрессии, подготовки/изучения и ограничений. Проверить обновление/удаление книг, отсутствующие источники, одинаковые имена и крупные реальные библиотеки. Варианты неизвестного правила сохраняются для ручного решения.
5. Приёмка новой композиции, светлой темы/палитр, крупных библиотек и движения на устройстве → отдельный Cycle → перенос принятого отрезка в основу. S12/G04/G10/P02 остаются открыты до полного пути.
