# Модель контента: C01–C04

29 октября 2026. Продолжение [CONTENT_MODEL_AND_LIBRARY_REPAIR_2026-10-15.md](CONTENT_MODEL_AND_LIBRARY_REPAIR_2026-10-15.md) и пунктов C01–C04 [реестра задач](WORKING_VERSION_TODO.md#5a-общая-модель-контента). Предметы, награды и Кузница (S01/S07/S09) строятся только поверх этого блока.

Исходное положение: индекс чтения (`ContentCatalog`) группирует записи книг в семейства по названиям и точным определениям, но пересчитывает группы при каждой сборке — ключи семейств временные. Ссылки героя держатся за ID записи конкретной книги; `ContentReferenceRepair` восстанавливает потерянные ссылки на заклинания только по точному совпадению.

## C01 · Постоянные ID семейств и вариантов — сделано

`lib/core/content/content_identity.dart`:

- **Вариант** — точное определение (редакция + полная подпись определения). Его ID детерминирован: `v1:<вид>:<хеш>`. Одна и та же книга даёт одинаковые ID на любом устройстве и при любом порядке импорта.
- **Семейство** — понятие каталога. ID выдаётся один раз (`f1:<вид>:<случайный>`) и хранится в реестре (`settings` → `content_identity`, формат версии 1).
- **Сверка** после загрузки каталогов и после установки или удаления книги (`ContentIdentityService.refresh`, рядом с восстановлением ссылок):
  - новое понятие → новое семейство (`create`);
  - книга-«мостик» связала два названия → семейства сливаются, старшее остаётся, младший ID продолжает разрешаться в него (`merge`);
  - мостик ушёл → семейство делится; часть с большинством вариантов сохраняет ID, остальные получают новые с пометкой, откуда они (`split`);
  - вариант из удалённой книги остаётся в реестре и по-прежнему указывает на своё семейство.
- **Журнал изменений** — последние 400 операций с датой; первое появление вида контента — одна запись `seed` с числом семейств, а не сотни `create`. Формат версионирован, реестр более новой версии не читается и не перезаписывается.
- Сверки идут строго по очереди; при запуске приложения сверка не задерживает первый кадр (реестр пока никто не читает до него).
- Хранилища, исходные записи, их старые ID и герои **не меняются**. Ошибка реестра не мешает запуску и импорту.

Проверки: `test/core/content/content_identity_test.dart` — устойчивость к пересборке и порядку, детерминированный вариант, слияние, разделение, удалённая книга, сохранение и неизвестная версия.

Прогон на полном архиве автора (`tool/check_content_identity_test.dart`, `QDND_PRIVATE_FC5_CORPUS=<папка>`; в репозиторий пишутся только числа): 33 источника, 1678 записей заклинаний → **604 семейства и 773 варианта** — ровно как индекс 15 октября. Всего по шести видам 1167 живых семейств и 1515 вариантов, реестр занимает ~630 КБ. Сверка — ~0,4 с на компьютере; повторная сверка ничего не меняет. После удаления модуля (проверено на разных модулях, до 453 заклинаний) все его записи по-прежнему разрешаются в свои семейства.

## C02 · Предметы на общей модели — сделано

- `Item` получил поля Hive 20 `familyId` и 21 `variantId` (в JSON пишутся только заданные, поэтому подпись определений книг не меняется). `id`, `instanceId`, `sourceId` и собственная копия определения у экземпляра остаются.
- `lib/core/content/item_references.dart`:
  - `stamp` — новый экземпляр (`ItemService.createItemFromTemplate`, приём героя из `.qdnd`) получает вариант своего определения и семейство из реестра;
  - `link` / `linkStoredCharacters` — перенос сохранённых инвентарей после каждой сверки реестра: ссылка ставится, только если собственная копия экземпляра **в точности** совпадает с известным определением (ID варианта однозначен по определению); иначе экземпляр не трогается. Связанные экземпляры следуют слиянию семейств. Герой, которого не удалось сохранить, откатывается;
  - `bookUpdate` — книга сменила определение, а копия экземпляра не менялась → лист предмета предлагает новую версию. Изменённая лично копия (через Кузницу), удалённая книга или актуальная копия — ничего не предлагают.
- **Решено (29.10):** отметка — плашка «В книге новая версия» в текущем листе предмета: книга, что изменилось (описание, вес, свойства оружия…), кнопка «Обновить». `InventoryActionsService.adoptBookVersion` берёт новую версию, сохраняя стопку, количество, экипировку и настройку (настройка снимается, только если новая версия её больше не требует); если лист изменился за это время — обновление отклоняется. Плашка перейдёт в новый дизайн вместе с инвентарём (S01).

Проверки: `test/core/content/item_references_test.dart` (ссылка, перенос только точных копий, предложение обновления, сохранение личных полей и отказ на изменившемся листе, JSON и Hive). На полном архиве: из 5 предметов героя FC5 ссылку получил 1 — остальные копии из файла героя не совпадают с книгами точь-в-точь; их разбирает C03.

## C03 · Импорт героя FC5 с явным выбором варианта — сделано

- Раньше адаптер ставил заклинанию первое определение, совпавшее по имени, а класс — по каноническому ID.
- Теперь (`lib/core/content/hero_reconciliation.dart`) парсер запоминает имена заклинаний из файла, и до сохранения героя `HeroReconciliation.settle` разрешает каждое имя через индекс:
  - нет совпадения — ссылка остаётся как была (её позже может восстановить `ContentReferenceRepair`);
  - одна версия (в том числе точные копии в нескольких книгах) — тихо;
  - **несколько отличающихся версий** — герою сразу ставится ведущая версия по настройке полки (не первая загруженная книга), запись попадает в список сверки.
- Классы героя разрешаются так же: семейство по каноническому имени, ведущая версия, при нескольких версиях — в сверку.
- Происхождение каждой ссылки на заклинание хранится в `spellbookData.contentReferences`: версия, `variantKey`, имена, `origin: fc5` и `originalNames` — как в файле.
- **Решено (29.10):** шаг «Сверка с библиотеками» сделан сразу в приложении (`lib/features/character_list/hero_reconciliation_page.dart`), без отдельного прототипа. После приёма героя из `.xml` открывается страница только со спорными записями (группы «Класс» и «Заклинания»): у каждой — что было в файле, книга, «N версий», «основная/ваш выбор». Нажатие открывает лист версий; стеклянный островок — «Принять основные» или «Принять · N изменений». Выход без принятия оставляет ведущие версии — они уже сохранены.
- Общий лист выбора версии (`showContentVariantPicker`, им же пользуются Альманах и выбор класса при повышении) переведён на стандарт волны 6: нажатие только выбирает карточку (форма и обводка меняются, текст раскрывается), подтверждение — стеклянный островок «Взять эту версию» / «Оставить эту».
- Предметы героя из файла остаются его собственными копиями; ссылку получают точные копии книжных определений (C02).

На полном архиве: у героя автора все 17 заклинаний найдены; в сверку попадают 8 заклинаний (по 2 версии) и класс «Чародей» (6 версий). Проверки: `test/core/content/hero_reconciliation_test.dart` (ведущая версия вместо первой, точные копии не спрашиваются, происхождение, смена версии, страница и сохранение). Снимки: `prototypes/c03/` (`test/render/c03_render_test.dart`, `QDND_RENDER_DIR=<папка>`).

## C04 · Списки создания на индексе — сделано

Классы, народы и предыстории в «Прологе» берутся из семейств индекса (`lib/core/content/shelf_choices.dart`):

- одна карточка на понятие; политика полки (базовые/мои) применяется первой и решает, какая версия ведущая;
- если понятие есть в нескольких книгах, на карточке написано «3 книги · 2 версии»;
- **решено (29.10):** нажатие сразу берёт ведущую версию без вопросов; повторное нажатие на выбранную карточку с несколькими версиями открывает их список («Выбрано сейчас» отмечено). Первую попавшуюся книгу молча никто не выбирает: ведущая определяется настройкой полки;
- группировка кешируется по набору записей, сборка главы её не повторяет.

На полном архиве: народы 159 строк → **54 карточки** (у 52 несколько версий — обычно другой текст), классы 58 → **26** (7 с версиями), предыстории 79 → **38** (3 с версиями).

Черт и отдельных предметов в «Прологе» нет: стартовые наборы ссылаются на конкретные шаблоны, выбор предметов — в инвентаре (C02/S01).
